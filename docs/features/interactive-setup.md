# Feature: Interactive Setup

**Status:** Implemented
**Owner:** Project lead
**Last Updated:** 2026-04-29

## Context

The teacher should never need to edit configuration files by hand. The interactive setup script is the single entry point for first-time installation, asking all necessary questions, validating answers, and ending with a fully running platform.

The setup is also the primary mechanism by which teachers re-configure the platform later — they can re-run `setup.sh` and overwrite `config.env` with new values.

## Behavior

### Pre-flight Checks

1. Verify Docker is installed; offer to install if missing.
2. Verify the user has Docker socket permissions (member of `docker` group).
3. Verify Docker Compose v2 is available.
4. Auto-detect server hardware: RAM, CPU count, timezone.

### Interactive Configuration

The script asks a series of questions, each with a sensible default:

1. **Number of students** (default: 60).
2. **Maximum simultaneous students** (default: 30).
3. **Two classes (A and B)** — yes/no, default yes.
4. **HTTP port** (default: 80).
5. **Initial student password** (default: `trocar123`).
6. **Admin password** (no default; minimum 8 characters; asked twice for confirmation).
7. **Per-student RAM limit** — auto-suggested based on detected RAM and concurrency.
8. **Per-student CPU limit** — auto-suggested based on detected CPU count.
9. **Idle timeout in minutes** (default: 60).
10. **Timezone** (default: detected via `timedatectl`).
11. **Cloudflare Tunnel** — yes/no, default no.
    - If yes: basic mode (anonymous URL) or token mode (fixed URL).
    - If token mode: prompts for the token.

### Confirmation and Build

After all questions, the script:

1. Displays a summary of all answers.
2. Asks for confirmation before continuing.
3. Writes `config.env` with all values.
4. Runs `./gerar.sh` to generate `docker-compose.yml` and supporting files.
5. Builds the portal Docker image.
6. Builds the student Docker image (Python + Pygame + PostgreSQL — takes 5-10 min on first run).
7. Creates all student containers in `created` state (not started).
8. Starts the infrastructure containers (Traefik, portal, optional cloudflared).
9. Displays final URLs and credentials.

### Inputs

- User answers via stdin (forced via `</dev/tty` to bypass any input redirection issues).

### Outputs

- `config.env` — main configuration file.
- `docker-compose.yml` — generated by `gerar.sh`.
- `alunos/alunoXX/workspace/LEIA-ME.md` — welcome files for each student.
- Built Docker images.
- Created student containers.
- Running infrastructure stack.

### Edge Cases

- **Docker not installed and user declines auto-install.** Script exits with instructions to install manually.
- **User not in `docker` group.** Script tells the user to run `sudo usermod -aG docker $USER` and log out/in.
- **Existing `config.env` from previous run.** Script overwrites without warning. Previous student data in `alunos/` is preserved.
- **Existing student containers from previous run.** They're recreated with the new configuration. Volumes (workspaces) are preserved.
- **User aborts at confirmation prompt.** No files are modified; the script exits cleanly.
- **Numeric values entered as non-numeric.** Re-prompts until valid.
- **Admin password too short.** Re-prompts until ≥8 characters.
- **Admin password confirmation doesn't match.** Re-prompts.

### Failure Modes

- **`gerar.sh` fails.** Setup exits with error; partial state left behind.
- **Docker build fails (e.g., network issue while pulling base image).** Setup exits with error; user can retry.
- **Container creation fails for some students** (e.g., name conflict with existing container). Counted but doesn't abort. Final message reports the count of failures.

## Re-running Setup

Re-running `setup.sh` is safe but disruptive:

- Existing `config.env` is overwritten.
- Containers are recreated (running ones are stopped).
- Student data in `alunos/` is preserved.
- The portal's session storage in `portal-data/` is preserved (so existing student passwords still work).

For non-interactive reconfiguration (e.g., changing only the timeout), editing `config.env` directly and running `./gerar.sh && docker compose up -d --force-recreate` is faster.

## Implementation Details

### Reading Input Robustly

The script uses `read -r VAL </dev/tty` instead of just `read -r VAL`. This forces reading from the controlling terminal, bypassing issues where stdin is otherwise redirected (which previously caused the script to hang after the first prompt).

### Hardware Auto-detection

```bash
RAM_KB=$(grep MemTotal /proc/meminfo | awk '{print $2}')
CPUS=$(nproc)
TZ_AUTO=$(timedatectl show --property=Timezone --value)
```

These values inform the suggested defaults but are not enforced — the user can override.

### Resource Suggestions

```
RAM_PER_STUDENT = (TOTAL_RAM_GB * 1024 * 70%) / SIMULTANEOUS_STUDENTS
clamp(256, 768)

CPU_PER_STUDENT = (CPU_COUNT * 70%) / SIMULTANEOUS_STUDENTS
clamp(_, 1.0)
```

The 70% factor leaves headroom for the host OS and the portal/Traefik containers.

## Integration Points

- **Generation:** `gerar.sh` is called at the end to produce all generated files.
- **Cloudflare HTTPS:** setup configures `CLOUDFLARE_TUNNEL` and `CLOUDFLARE_TOKEN`.
- **Authentication:** initial student passwords and admin password are configured here.
