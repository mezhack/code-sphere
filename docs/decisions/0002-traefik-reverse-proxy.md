# ADR-0002: Traefik for Reverse Proxy and Routing

**Status:** Accepted (revised 2026-05-08)
**Date:** 2026-04-25
**Decision Makers:** Project lead

## Context

The system has one public entry point (port 80) but routes traffic to many internal services: the Flask portal, and one code-server container per logged-in student. Routes look like `/admin` for the portal and `/code/aluno01/`, `/code/aluno02/`, etc. for student environments.

Student containers are pre-declared in `docker-compose.yml` but only started on demand. The reverse proxy must know about all routes upfront, without requiring restart when a student logs in.

The proxy must also handle WebSocket connections (code-server uses WebSockets heavily for real-time UI updates and terminal sessions).

## Decision

Use **Traefik v3.2** as the reverse proxy. All routes (portal and all student slots) are declared statically in `traefik/dynamic/routes.yml`, a file generated by `gerar.sh` before any container starts. Traefik reads this file at startup via the **file provider** (`providers.file.filename`).

The file provider was chosen over the Docker provider after a compatibility failure on Docker Engine 29.x (see Known Issues below).

Example of a generated route entry:

```yaml
http:
  routers:
    portal-router:
      rule: "Path(`/`) || PathPrefix(`/login`) || ..."
      service: portal-svc
      entryPoints: [web]

    aluno01-router:
      rule: "PathPrefix(`/code/aluno01`)"
      service: aluno01-svc
      middlewares: [strip-aluno01]
      entryPoints: [web]
      priority: 100
```

## Alternatives Considered

### Docker label-based routing (original approach)

Pros: rules live next to the containers that describe them; containers can register themselves dynamically.

Rejected because: Traefik's internal Docker API client uses a fixed API version (v1.24) that Docker Engine 29.x refuses as too old (minimum required: v1.40). Setting `DOCKER_API_VERSION=1.41` in the environment has no effect because Traefik uses `WithAPIVersionNegotiation()` internally. The Docker provider is therefore unusable on modern Docker Engine without rebuilding Traefik itself.

### nginx with templated config

Pros: extremely well-known, vast documentation, mature.

Rejected because: dynamic routing (containers appearing and disappearing) requires either reload-on-change (which drops connections) or a sidecar like `nginx-proxy`. For this system, student container slots are all pre-declared, so any static proxy would need full regeneration on configuration change anyway.

### Caddy

Pros: similar capabilities to Traefik, simpler config syntax, automatic HTTPS support.

Rejected because: Docker label support is less mature than Traefik's, and the project doesn't need Caddy's automatic HTTPS (we use Cloudflare Tunnel instead, see ADR-0004).

### HAProxy

Pros: extremely fast, battle-tested at scale.

Rejected because: dynamic configuration story is weaker, and we don't need its performance ceiling.

### No reverse proxy (port-per-student)

Pros: simplest possible architecture.

Rejected because: would require students to remember per-student port numbers (e.g., `192.168.1.41:8001` for student 01). Many school networks block non-standard ports. URL paths are universally accessible.

## Consequences

### Enabled

- Single port (80 or 443) is enough for the entire deployment.
- No Docker socket needed by Traefik — removes a privilege boundary.
- Compatible with Docker Engine 24+ through 29+ without version pinning.
- Routes are version-controlled (generated by `gerar.sh`) and predictable.

### Prevented

- Routes cannot auto-discover at runtime. Adding a new student slot requires running `./gerar.sh` and restarting Traefik. This is acceptable because the number of students is set once at setup time.
- Cannot easily run two independent classroom installations on the same machine without editing the generated port assignments.

### Known Issues

- **WSL2 bind-mount of the dynamic directory is unreliable.** On WSL2, Docker containers sometimes see an empty directory when a directory bind-mount is used and the file was created shortly before container start. Fix: mount the file directly (`./traefik/dynamic/routes.yml:/etc/traefik/dynamic/routes.yml:ro`) instead of the directory. This is the current default generated by `gerar.sh`.

- **`watch: false` on WSL2.** Traefik's `watch: true` relies on inotify, which does not propagate through WSL2's 9P filesystem. Since `iniciar.sh` always recreates the Traefik container with `--force-recreate`, the file is read fresh on every startup. Hot-reload of routes without restart is not available.
