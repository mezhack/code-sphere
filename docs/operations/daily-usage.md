# Daily Usage

This guide covers the operations a teacher performs during normal day-to-day use of the platform.

## Starting Up (Beginning of Day)

```bash
cd ~/sala-de-aula
./iniciar.sh
```

This starts the infrastructure: Traefik, the portal, and (if enabled) the Cloudflare Tunnel. Student containers stay parked — they'll start automatically when students log in.

If Cloudflare Tunnel is in anonymous mode, get the current URL:

```bash
./url_atual.sh --watch
```

Display this URL in class for students to access.

## Pre-warming Before Class

10–15 minutes before class starts, pre-warm the containers for the class you're teaching:

```bash
# For Class A (students 1–30)
./preaquecer.sh turma_a

# For Class B (students 31–60)
./preaquecer.sh turma_b

# For both classes
./preaquecer.sh
```

Pre-warming starts the containers in advance. When a student logs in, the portal detects the container is already running and performs a **fast restart**: it updates the authentication token inside the running container and restarts only the code-server process via `s6-svc`. This takes ~1–2 seconds instead of the 15–45 seconds required to recreate the container from scratch.

Without pre-warming, every first login of the day triggers a full container recreation. Students see a loading screen for 30–45 seconds.

## During Class

### Monitor Activity

Open the admin panel in your browser:

```
http://<server-ip>/admin
```

The panel shows:
- Total students and how many are online
- Per-student status: online/offline, CPU%, RAM, idle time, last login
- Server-side total RAM and free RAM

The panel auto-refreshes every 30 seconds.

### Reset a Forgotten Password

In the admin panel, find the student's row and click "🔑 Senha". The student's password is reset to the initial password (`trocar123` or whatever you configured), and they're forced to set a new one on next login.

### Restart a Stuck Container

If a student reports their VS Code is unresponsive:

1. Find their row in the admin panel.
2. Click "↺ Reiniciar".
3. Tell them to refresh their browser.

The container restarts in the background; auto-reconnect picks it up automatically.

### View What a Student Is Doing

Find their row, click "📁 Arquivos". Browse the workspace tree. Click any `.py` file to see the code with syntax highlighting. Press `R` in the file viewer to refresh after the student saves.

Note: the viewer shows files **as last saved**. If the student hasn't saved (Ctrl+S) since their last edit, you'll see the old version. The auto-save default is 1 second after typing stops, so this is rarely an issue in practice.

## Ending the Day

```bash
./parar.sh
```

Stops all containers. Student work is preserved in `./alunos/`.

## Weekly Maintenance

### Backup Student Work

```bash
./backup.sh
```

Creates a compressed tar of `./alunos/` in the `./backups/` directory, timestamped. Keep these in a safe location (external drive, school network share).

### Check for Updates

The admin panel shows a yellow banner when a newer version is available. Click "Ver novidades" to see the GitHub release notes. To update, see [Upgrading](./upgrading.md).

### Free Disk Space (if needed)

Docker images and stopped containers can accumulate. Periodically:

```bash
docker system prune -f
```

This removes unused images and dangling layers. Student data and current images are preserved.

## Emergency Operations

### Stop Everyone (e.g., end of class is approaching)

In the admin panel, click "⏹ Parar todos". All running student containers are stopped at once. Students see the loading screen and can re-login if needed.

### Reset All Passwords (e.g., after a major security incident)

In the admin panel, type `RESETAR TODAS` in the confirmation field and click "🔑 Resetar todas senhas". Every student is set back to the initial password and forced to change on next login.

### Quick Sanity Check

```bash
# Are the infrastructure containers running?
docker ps | grep -E 'sala_traefik|sala_portal'

# Are any student containers active?
docker ps | grep sala_aluno | wc -l

# Is the portal responding?
curl -s http://localhost/healthz
# Should print: {"ok":true}
```

## Common Patterns by Day

**Class day:**
1. `./iniciar.sh` (if the server was off)
2. `./preaquecer.sh turma_a` (15 minutes before class)
3. Display the URL on the projector
4. Monitor `/admin` during class
5. `./preaquecer.sh turma_b` (between classes)
6. After all classes: `./parar.sh` (or leave running if comfortable)

**Non-class day:**
- Run `./backup.sh` weekly.
- Check the admin panel for the version banner.
- Do not start containers if not needed (saves wear on the machine).

## What Not to Do

- **Don't edit `docker-compose.yml` by hand.** It's regenerated by `gerar.sh`. Edit `config.env` and re-run `./gerar.sh` instead.
- **Don't delete `portal-data/` casually.** It contains all student passwords. If you must delete it, students must reset their passwords.
- **Don't `docker compose down -v`.** The `-v` flag removes volumes; with bind mounts it doesn't, but it's a habit you don't want.
- **Don't change ownership of `./alunos/` to your user.** It must stay UID 911. See [ADR-0007](../decisions/0007-puid-pgid-911.md).
